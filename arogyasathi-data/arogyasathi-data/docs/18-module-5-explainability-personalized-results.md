# Module 5: Explainability, Personalized Results & Action Guidance

## Overview
Module 5 introduces the Explainability Layer to ArogyaSathi. It bridges the gap between deterministic rule engine logic and citizen-friendly UX. The engine output is enriched with localized headlines, structured next steps, deep-linked profile editing actions, and clear condition breakdowns, ensuring that citizens never see raw rule IDs or abstract logic flags.

## Explainability Architecture
1. **Raw Structured Result**: Generated by the `EligibilityService`. Contains `MATCH` / `FAIL` statuses per rule condition.
2. **Explanation Service**: The `ExplanationService` separates the conditions logically:
   - `Matched Conditions` (`PASS`)
   - `Failed Conditions` (`FAIL`)
   - `Missing Information` (`UNKNOWN` + `FIELD_UNKNOWN` reason code)
   - `Verification Needs` (`UNKNOWN` + `OFFICIAL_VERIFICATION_REQUIRED` reason code)
3. **Frontend Result Redesign**: The UI dashboard consumes the structured explanation. It categorizes schemes into `MATCH`, `NEEDS_VERIFICATION`, and `NOT_MATCHED`, showing clear counts and animated reveals.

## Key Features

### Deterministic Next-Step Engine
Next steps are algorithmically generated based on the evaluated status and the specific rule breakdowns:
- If `NOT_MATCHED`: Shows "Edit your profile if your information was incorrect."
- If `Missing Information`: Specifically links back to the profile editing flow to provide exact data.
- If `Verification Needed`: Provides an explicit "Open Portal" link mapped directly from the verified scheme database (`application_channels.portal`).

### Multilingual Support & Headlines
Headlines dynamically adapt to status and are fully supported in English, Tamil, and Hindi:
- MATCH: "This scheme matches the information you provided." ("நீங்கள் வழங்கிய தகவல்களுடன் இத்திட்டம் பொருந்துகிறது.")
- NEEDS VERIFICATION: "This scheme may match, but some information still needs verification."

### Edit & Re-Evaluate Flow
The "Edit Profile" CTAs push the citizen back to `/eligibility` using ephemeral `sessionStorage`. Since the state is hydrated natively upon return, they can instantly update e.g., missing Income, click Save, and instantly see the results re-evaluate live without reloading or clearing previous correct fields.

### Transparent Benefits Presentation
Top-line benefits (like "Coverage: ₹5,00,000" and "Cashless Treatment") are surfaced directly on the MATCH card to provide immediate value-prop clarity before the user even clicks into the full scheme details.

## Known Limitations
- The underlying deterministic engine restricts its operator reason codes (like `EQ_MATCH`) to backend models. Localized string extraction from the DB schemas (e.g., `user_friendly_explanation`) currently relies on English. A future localization module (or LLM simplifier) could safely translate these rule-specific strings on the fly without changing logic.
